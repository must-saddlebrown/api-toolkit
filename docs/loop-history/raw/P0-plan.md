## Scope

Masuk P0 (PLAN §11 P0, §13):
- Satu Rust package, satu binary `api-toolkit`, modul `config`, `http`, `matchers`, `checks/{brute_force,race,load}`, `report`, `cli` (§13). Modul `checks/*` hanya kerangka kosong (`mod.rs`/file stub berisi komentar), tanpa logika check (P1–P3).
- Schema config v1 (§9) sebagai struct Rust + validasi semantik (§8 batas angka, §9 aturan error) + resolusi `${ENV:NAME}`.
- Command `validate --config <path>` (§3): nol request. Command `check` hanya didefinisikan di clap sebagai stub yang keluar dengan kode 2 dan pesan "belum diimplementasi" (implementasi di P4; tidak boleh exit 0).
- Shared HTTP transport (§8): satu request, timeout, body limit, tanpa redirect, tanpa retry, TLS verify aktif.
- Matcher kecil (§4): `status_in`, `json_equals`, `json_exists`, digabung AND, JSON Pointer.
- Report model + enum verdict/reason code + atomic write (§10), diuji dengan golden test.
- Fixture lokal healthy (login, action write-once + verifier counter, endpoint load) dengan start/reset terdokumentasi (§11 P0).

Di luar P0:
- Logika check, orchestrator, console summary, exit code suite (130, 1), partial report/cancel: P1–P4.
- Fixture varian broken/idempotent/slow/prelocked: ditambahkan di slice P1–P3 yang membutuhkannya.
- Verdict matrix: N/A untuk P0 (hanya P1–P3, karena belum ada check yang menghasilkan verdict). P0 hanya mengunci kontrak enum (lihat di bawah).
- Dilarang oleh scope guard: TUI, OpenAPI, flow builder/DSL, assertion language, JUnit, history DB, CVSS, AI, plugin interface, trait tanpa implementasi kedua.

## Kontrak enum yang harus dikunci P0 (PLAN §4, §10)

Semua diserialisasi `#[serde(rename_all = "snake_case")]`. Mengubah atau menghapus varian = perubahan kontrak report (naik `report_version`). Menambah varian di P1–P3 boleh (aditif), dicatat di DECISIONS.

`Verdict` (§4): `pass`, `fail`, `inconclusive`, `error`, `not_run`. Console boleh menampilkan huruf besar; JSON selalu snake_case.

`CheckName`: `brute_force`, `race`, `load`.

`Completion` (status lengkap suite/check): `complete`, `incomplete`.

`ReasonCode` (set awal; nama dari PLAN bila ada, sisanya turunan dari §5–§7):
- Umum: `config_invalid`, `deadline_exceeded`, `cancelled`, `not_started`, `report_write_failed`, `transport_error`, `overlapping_rules`.
- brute_force: `protection_observed` (PASS), `invalid_credentials_accepted`, `protection_policy_not_met`, `account_already_locked`, `baseline_failed`, `probe_unclassifiable`.
- race: `single_side_effect` (PASS), `duplicate_side_effect`, `action_not_executed`, `initial_counter_not_zero`, `dispatch_incomplete`, `dispatch_skew_exceeded`, `action_outcome_ambiguous`, `verifier_failed`, `counter_invalid`.
- load: `thresholds_met` (PASS), `error_rate_exceeded`, `latency_exceeded`, `target_not_ready`, `workload_incomplete`, `preflight_failed`, `runner_error`.

`Outcome` per attempt (§5 langkah 4, §10): `success`, `normal_rejection`, `protection`, `unexpected`, `transport_error`. `TransportErrorCode` (sanitized, tanpa URL/pesan library): `timeout`, `connect_failed`, `tls_failed`, `body_too_large`, `body_read_failed`, `request_invalid`, `other`.

Kerangka report v1 (§10) yang dikunci P0: `report_version` (=1), `run_id`, `tool_version`, `config_hash` (SHA-256 hex dari byte file config mentah; aman karena config hanya berisi referensi env), `started_at`/`finished_at` (RFC3339 UTC), `completion`, `checks: [ {check, verdict, reasons: [ReasonCode], completion} ]`. Field evidence per-check ditambahkan aditif di P1–P3. Tidak ada field untuk body/header/secret.

## Risiko dan hal yang diuji

- Build `reqwest` `rustls` bisa butuh toolchain C (aws-lc-rs): dibuktikan di S1; fallback dicatat.
- `sha2 0.11` API baru: hex lewat loop byte; fallback 0.10.
- Pesan error serde bisa mengutip nilai literal config. Config hanya boleh berisi nilai nonsecret (secret lewat `${ENV:}`), tetapi implementer tidak boleh menyalin nilai env ke error apa pun.
- False PASS: `check` stub tidak boleh exit 0 (P0-AC16); `validate` sukses tidak berarti target siap.
- Aturan overlap konservatif dapat menolak config sah pengguna nyata; ditinjau di P4.
- Port 8080 mungkin terpakai: fixture punya `--port`; test memakai port 0 (acak).
