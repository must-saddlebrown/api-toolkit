Tidak ada jalur "respons tak terklasifikasi" di load: hanya ada satu matcher, jadi setiap respons adalah success atau failed (L11). Overlap matcher tidak berlaku.

Aturan presedensi `evaluate` (langkah pertama yang berlaku menentukan verdict):
1. Invarian runner dilanggar → `error [runner_error]`, `complete`.
2. Preflight tidak ada: dengan stop → `not_run [stop]`; tanpa stop → `not_run [not_started]` (pertahanan); `incomplete`.
3. Preflight transport error → `error [preflight_failed, transport_error]`, `complete`.
4. Preflight tidak cocok → `inconclusive [target_not_ready]`, `complete`.
5. `attempted < requests`: dengan stop → `not_run [stop, workload_incomplete]`; tanpa stop → `inconclusive [workload_incomplete]`; keduanya `incomplete`.
6. Workload lengkap: reasons = `error_rate_exceeded` bila `error_rate > max_error_rate`, lalu `latency_exceeded` bila `p95_ms > max_p95_ms`. Ada reason → `fail`; kosong → `pass [thresholds_met]`. `complete`.

Stop yang datang setelah semua N tercatat masuk langkah 6 (verdict normal), sesuai preseden P1/P2.

| Topik | Keputusan | Alasan |
| --- | --- | --- |
| Struktur modul | Semua di `src/checks/load.rs`: `classify` (murni), `nearest_rank_ms` (murni), `ceil_ms` (murni), `evaluate` (murni), `run_with` (async, closure pengirim), `run` (membungkus `http::send`), `console_line`. Pakai `Stop`, `current_stop`, `wait_stop` dari `checks/mod.rs`. | Pola P1/P2; matrix teruji tanpa jaringan; satu file per check (§13). |
| Signature | `pub async fn run(transport: &Transport, cfg: &config::Load, request: &ResolvedRequest, stop: watch::Receiver<Option<Stop>>) -> CheckResult`. `run_with<F, Fut>(send_one: F, cfg: &Load, stop)` dengan `F: Fn(Kind) -> Fut`, `pub enum Kind { Preflight, Load(u32) }` (nomor request 1..=N). Prasyarat: config lolos `validate`. | Nomor request membuat skrip test deterministik walau urutan selesai berbeda; `Fn` karena worker meminjam closure bersamaan (preseden P2). |
| Bounded parallelism | Worker pool eksplisit dalam satu task: `w = min(concurrency, requests)` future worker, dijalankan dengan `futures_util::future::join_all` (sudah dependency). Nomor berikutnya diambil lewat `AtomicU32::fetch_add(1, Relaxed)` bersama; worker berhenti bila nomor > N atau stop aktif. Tiap worker mengembalikan `(dispatched, Vec<Sample>)` miliknya; digabung setelah `join_all`. Tanpa `spawn`, tanpa `Semaphore`, tanpa dependency baru. | Cocok harfiah dengan "closed-loop worker pool" (§7); `spawn` butuh `'static` padahal `Secret` tanpa `Clone`; `buffer_unordered` setara secara perilaku tetapi menyembunyikan worker dan mempersulit stop per worker. `AtomicU32` (bukan `Cell`) agar future tetap `Send` bila P4 butuh. |
| Ukur concurrency | `in_flight: AtomicU32` dinaikkan tepat sebelum `send`, diturunkan setelah `send` selesai atau di-drop karena stop; `max_in_flight` lewat `fetch_max`. | Bukti AC6 di sisi client; dibandingkan juga di invarian `evaluate` (L22). |
| Stop | Sebelum preflight dan sebelum tiap dispatch: `current_stop` → berhenti. `send` dibungkus `select! { biased; wait_stop => drop, r = send => r }`. Request yang di-drop dihitung di `dispatched`, tidak jadi sampel. | Pola P1/P2; §8 "Cancel menghentikan dispatch baru ... menyimpan hasil parsial". |
| Klasifikasi outcome | `classify(&Result<TransportResponse, TransportError>, &MatcherSpec) -> SampleOutcome { Success(u16), Mismatch(u16), Transport(TransportErrorCode) }`: `Ok` + `matches(status, body.as_ref())` → Success; `Ok` lain → Mismatch; `Err` → Transport. Timeout = `Transport(Timeout)`. Body dibuang setelah klasifikasi. | §7 "Failed mencakup matcher mismatch, status unexpected, transport failure, dan timeout"; kontrak matcher P0 S5 (body `None` = tidak cocok). |
| Error rate | `error_rate = failed as f64 / attempted as f64` (hanya bila `attempted > 0`, selain itu `None`); berlebih bila `error_rate > max_error_rate`. | Pembagian IEEE dibulatkan benar dan monoton, jadi rasio yang sama persis dengan threshold desimal (1/100 vs `0.01`) menghasilkan double yang sama dan lolos; tanpa epsilon. |
| p95 | Nearest-rank: salin durasi, `sort_unstable`, rank = `(pct * n).div_ceil(100)` (1-based, `n >= 1`), ambil indeks `rank-1`, lalu `ceil_ms`. p50 sama dengan pct 50; max = elemen terakhir. Sampel = semua request yang tercatat (sukses, mismatch, transport, timeout). Berlebih bila `p95_ms > max_p95_ms`. | §7 "p95 dihitung nearest-rank pada durasi semua attempted request ... termasuk timeout/error". |
| Pembulatan ms | `ceil_ms(d) = d.as_nanos().div_ceil(1_000_000)` (saturasi ke `u64`). Dipakai untuk p50/p95/max. Evidence preflight memakai floor seperti P1/P2. | Ceil mencegah 500,4 ms tampil 500 lalu PASS; nanos (bukan micros seperti race) agar 500,0004 ms juga tertangkap. |
| Timing | `tokio::time::Instant` di worker: `t = Instant::now()` sebelum `send`, `t.elapsed()` setelah hasil (body sudah dibaca oleh `send`). `load_elapsed_ms` = awal load (setelah preflight) sampai `join_all` selesai. `throughput_rps = attempted * 1000 / load_elapsed_ms` sebagai `f64`, `None` bila elapsed 0. | §7 langkah 3–4; bisa di-pause di unit (pola P1). |
| Preflight | Tepat satu `send(Kind::Preflight)` sebelum worker mulai; cocok `response_match` = siap. Tidak masuk sampel/denominator/histogram; evidence-nya terpisah (`VerifyEvidence`: status, error, offset, elapsed). Gagal = nol request load. | §7 langkah 1; memakai ulang tipe yang ada. |
| Definisi incomplete | `attempted` = jumlah sampel tercatat; `dispatched` = nomor yang sudah diambil worker (termasuk yang di-drop). Workload lengkap hanya bila `attempted == requests`. | §7 "N scheduled harus seluruhnya dicoba sebelum PASS". |
| Stop → NOT_RUN | Stop saat load = NOT_RUN `[stop, workload_incomplete]`, bukan INCONCLUSIVE. Sampel < N tanpa stop = INCONCLUSIVE `[workload_incomplete]`. | §3 dan §4 ("NOT_RUN: dibatalkan atau deadline habis") serta preseden P1/P2; `workload_incomplete` mencatat bahasa §7. ## Risiko dan hal yang diuji

- False PASS lewat deadline dini: ditutup langkah 5 `evaluate` (L19) dan invarian `attempted == requests` untuk PASS.
- False PASS lewat pembulatan p95: ceil berbasis nanos (L9); error rate tanpa epsilon (L5/L6).
- False PASS lewat bug penghitungan worker: invarian `evaluate` (L22) → ERROR, bukan PASS.
- Flaky integrasi: test PASS memakai threshold longgar; test FAIL hanya mengandalkan batas bawah delay server atau counter. Preflight bisa timeout di mesin yang sangat sibuk → hasil ERROR (test merah), bukan PASS palsu.
- Rute hang: handler tidur 3 s; graceful shutdown fixture mungkin menunggu handler itu, sehingga test hang bisa butuh beberapa detik ekstra. Dibatasi dengan `requests=20` (dua request hang, paralel).
- Pooling mati: 101–1001 koneksi TCP baru per run; aman di loopback; untuk API nyata durasi mencakup connect (sesuai §7) dan p95 bisa lebih tinggi daripada klien dengan keep-alive. Dicatat di STATUS.
- Lepas `Eq` dari `Report`/`CheckResult`: reviewer cek tidak ada assertion yang dihapus dan semua golden lama identik.
- Semantik `load_requests` berubah (kini termasuk 401): `fixture_smoke` diperbarui mekanis di S5.
- `max_in_flight == 10` di integrasi: deterministik karena `join_all` mem-poll semua worker sekali sebelum ada yang bisa selesai; bila suatu saat merah, longgarkan ke `<= 10` dan andalkan unit S4.
- Throughput dan durasi bergantung mesin; hanya informatif, tidak menentukan verdict selain p95.
