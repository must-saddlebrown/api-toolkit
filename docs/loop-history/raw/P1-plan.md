Aturan presedensi `evaluate`, dievaluasi berurutan; langkah pertama yang berlaku menentukan verdict:
1. Stop sebelum baseline selesai → `not_run`, reasons `[stop]`, `incomplete`.
2. Baseline tidak sukses (probe tidak dikirim, `complete`): protection → `inconclusive` `[account_already_locked]`; rejection → `inconclusive` `[baseline_failed]`; unexpected → `error` `[baseline_failed]` (+ `overlapping_rules` bila penyebabnya overlap); transport → `error` `[baseline_failed, transport_error]`.
3. Ada probe `success` → `fail`. Reasons: `invalid_credentials_accepted`, lalu bila berlaku `probe_unclassifiable`, `transport_error`, `overlapping_rules`, `account_already_locked`, lalu reason stop. `incomplete` bila stop, selain itu `complete`.
4. Stop sebelum semua probe selesai → `not_run`, reasons `[stop]`, `incomplete`. Error/inconclusive parsial tidak dipromosikan; attempt parsial tetap ada di evidence.
5. Ada probe `unexpected`/`transport_error` → `error`. Reasons: `probe_unclassifiable`, lalu bila berlaku `transport_error`, `overlapping_rules`, `account_already_locked` (probe 1 protected).
6. Probe 1 `protection` → `inconclusive` `[account_already_locked]`.
7. Semua probe terklasifikasi tanpa success: first protected ≤ `protect_by_attempt` dan `protected_tail_count` attempt terakhir protected → `pass` `[protection_observed]`; selain itu `fail` `[protection_policy_not_met]`.

Hanya bukti definit (invalid accepted) yang mengalahkan stop. Completion `incomplete` hanya bila ada stop; semua jalur lain `complete` (check selesai sesuai algoritmanya, termasuk berhenti setelah baseline gagal).

## Risiko dan hal yang diuji

- False PASS lewat run terhenti: stop selalu `incomplete`; `exit_code` P0 sudah memetakan `incomplete`/`not_run` ke 2 dan `cancelled` ke 130. Test M19–M23.
- Paused clock + IO nyata memicu timeout palsu: integration fixture tidak memakai `pause`.
- `TransportResponse` dan `CheckResult` harus tetap tanpa body/token di `Debug`: sentinel test S3/S5.
- `CheckResult` derive `Eq`: evidence P1 hanya integer/enum (aman). Evidence load P3 (f64) akan memaksa melepas `Eq`; bukan urusan P1.
- Fixture healthy berbagi hitungan gagal antar test dalam satu proses fixture: setiap integration test memulai fixture sendiri (port 0).
- Tetap mengirim semua probe setelah probe 1 protected memperpanjang lockout akun nyata; diterima (workload tetap, dicatat di DECISIONS).
- Celah proteksi di tengah (M16) PASS karena PLAN hanya menuntut first ≤ protect_by dan tail; dicatat sebagai keterbatasan, bukan bug.
